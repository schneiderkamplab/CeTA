TRS_Spec_Base.thy
-----------------
- type ranked_signature
  Change to
    "'f \<Rightarrow> nat"
  Argument: if we have a type S, we can always make the subtype {x:S | f x = Some n}. So all results still hold.
  Also, shouldn't this be called "arity"? It _is_ the arity function...

- there should be a type definition "'f 'v rewriting_rules" for
    "'f 'v ((('f,'v) fo_term \<times> ('f,'v) fo_term) set)"
  (a set of rewriting rules). This is done for conditional and equational rewriting systems

- definition trs_problem
  Remove first conjunct:
    infinite (UNIV :: 'v set)
  The infinity of a set of variables should be a separate hypothesis, and assumed when needed. I am also not sure about this formulation (why add UNIV?).

- definition logic_mgu
  "logic_subst" and "logic_eval" are used indistinctively...
  I don't get the complexity. There should only be one substitution as argument. I would expect something like
    logic_mgu D t1 t2 s \<longleftrightarrow>
      logic_substitution D s \<and>
      logic_atom_map (logic_subst s) t1 = logic_atom_map (logic_subst s) t2 \<and>
      (\<forall>u. logic_substitution D u \<longrightarrow>
        logic_atom_map (logic_subst u) t1 = logic_atom_map (logic_subst u) t2) \<longrightarrow>
	(\<exists> v. logic_substitution D v \<and>
	  [u = v \<circ> s, however this is written]))
