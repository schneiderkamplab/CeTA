# CPF 6: logic programming additions

CPF 6 inherits CPF 5, which inherits CPF 4 and all CPF 3 constructs. CPF 4
adds first-order term and string rewriting; CPF 5 adds ITS and higher-order
rewriting; CPF 6 additionally covers logic programming, LP with cut, and Prolog.
These are additive version boundaries: no original CPF 3 feature is removed.

## Current implementation

`cpf6.xsd` is generated by `scripts/generate_cpf6_schema.py` from `cpf5.xsd`,
with `cpf6-logic-programming.xsd` supplying the implemented LP additions.
Currently the translation constructors `lpFiniteTerminationProof` and
`lpTocl09TerminationProof`, the three Pi-DP/composition constructors, TOCL09 mode refinement, initial dependency triples, the four graph/constructor forms, and the seven nontermination forms listed below,
have CPF 6 envelopes, as do ordered-cut source nontermination, three cut graph forms, and basic/free/projected SEG forms. This is not
yet complete integration of every LP, cut,
or Prolog certificate.

The envelope uses `cpfVersion` 6.0, an empty `lookupTables`, a
`logicProgramInput`, a termination property, a constructor-appropriate YES or NO answer, and one proof.
The input has these fields, in order:

- `resolutionSemantics`: `finiteTerms` or `infiniteTrees`.
- `program`: ordered clauses, each with a head atom and an ordered body.
- `query`: predicate symbol, arity, and zero-based ground argument indices.

For translation proofs (YES), the proof contains `returns`, `fallback`, `continuations`, `argumentFilter`,
and an embedded `trsTerminationProof`, in order. It does not duplicate the
program or query. The finite constructor requires `finiteTerms`; the TOCL09
constructor requires `infiniteTrees`. The formal semantic correspondence is
in `LP_Finite_Checker.thy` and `LP_TOCL09_Checker.thy`. Atom and term symbols
retain the existing source translation encoding.

`Ceta.Input.Cpf6.logicProgramming` checks the envelope version, claim and
constructor/semantics agreement. It then reconstructs the existing structured
LP fragment using the input's program and query, and passes it to the unchanged
Isabelle-generated checker. A valid envelope or schema alone never establishes
termination. Source correspondence to a separate input file is checked by
Ferrum's source audit, independently of proof acceptance.

Run a supported certificate with `ceta --category lp proof.xml`. Existing
standalone LP fragments remain accepted during migration. LeTA directly decodes the integrated CPF 6 forms and independently checks
their source semantics and witnesses. Translation proofs reconstruct the
canonical filtered TRS and check its embedded proof. Its remaining first-order child
coverage limits still apply. Removing automatic legacy acceptance, completing
the other LP/cut/Prolog forms and the full hash-pinned replay remain release
requirements.


## Pi-DP and nested LP obligations

The following YES constructors require `infiniteTrees`:

| Constructor | Ordered witness fields |
| --- | --- |
| `lpTocl09PiDpTerminationProof` | `returns`, `fallback`, `continuations`, `marks`, `argumentFilter`, `ranks`, `components` |
| `lpTocl09PiDpModeTerminationProof` | `modes`, `certificationProblem` |
| `lpTocl09SimplificationProof` | `certificationProblem` |

Each nested `certificationProblem` is a complete CPF6 document element with its
own source program, query, semantics, property and answer. Mode refinement
requires a Pi-DP child; simplification requires a mode-refinement child. The
checker verifies the parent/child relationship; matching XML tags alone is
insufficient. Components contain `noCycle` or an embedded ordinary `dpProof`.
Ranks and argument filtering retain the native Pi-DP semantics, including
non-minimal component obligations. See `LP_PiDP_XML.thy` and
`LP_Source_Simplify_XML.thy` and LeTA's independent Pi-DP and simplification
criteria.

The historical positive compatibility gate accepts all 78 certificates using
these three forms in both checkers, twice each. Its larger 235-root sample
now passes both checkers completely, including the two translation proofs
that previously required monotone/usable-rule child decoding. This is not a fresh
full production replay. The reproducible gate is
`CeTA-Lean/scripts/test_cpf6_lp_yes.py`; retained results are in
`CeTA-Lean/docs/cpf456-integration/monotone-summary.json`.

## TOCL09 mode refinement

`lpTocl09ModeTerminationProof` adds `modes` followed by a complete nested
`certificationProblem`. The child must be `lpTocl09TerminationProof` with
infinite-tree semantics and a YES termination claim. Every mode entry maps a
refined predicate to its source predicate. The checker verifies complete mode
coverage, the query mapping, and equal parent/child arity and ground positions.
It then checks the child's canonical translation and TRS proof independently.

This follows `LP_Mode_Checker.thy`. LeTA's
`LogicProgramming/ModeTerminationCheck.lean` proves the same mode-cover transfer
using its independent termination checker. The native codec test, Lean proof
build and focused LeTA acceptance/rejection and fresh strict replay gates pass.
The final focused gate passes 40 checks across CeTA and LeTA, plus fresh
synthesis and strict guided replay checked twice by each checker. Evidence is
retained in `CeTA-Lean/docs/cpf456-integration/mode-summary.json`. Together with
the previous checkpoint, sixteen forms have dual-checker evidence. Reproduce the focused tests with
`CeTA-Lean/scripts/test_cpf6_lp_mode.py` and
`CeTA-Lean/scripts/test_cpf6_lp_mode_cli.py`.

## Source graphs, answer graphs and constructor dependency pairs

These three YES forms require `infiniteTrees`:

| Constructor | Ordered witness fields |
| --- | --- |
| `lpTocl09SourceGraphProof` | `fuel`, `root`, `nodes` |
| `lpAnswerGraphTerminationProof` | `fuel`, `root`, `nodes`, `certificationProblem` |
| `lpConstructorQDpTerminationProof` | `returns`, `fallback`, `continuations`, `marks`, `argumentFilter`, `seed`, optional `normalSubstitutions`, `dpProof` |

Graph child index zero denotes no child; positive indices identify nodes using
one-based indexing. Source nodes carry goals, a prefix and children. Answer
graph nodes additionally record interface variables, a symbol and one action:
`success`, `resolve`, `instance` or `split`. Their complete nested CPF6 proof
must be a TOCL09 translation or constructor-QDP proof. Both checkers verify
the graph bridge and the child program/query relationship.

The constructor checker reconstructs filtered rules, pairs and Q patterns from
the source. An omitted `normalSubstitutions` means false; explicit false and
true retain their distinct serialized forms. Recursive DP processing preserves
Q and normality assumptions. The Isabelle correspondence is in
`LP_Source_Graph_XML.thy`, `LP_SEG_Residual_XML.thy` and `LP_Constructor_XML.thy`;
LeTA uses its independent source-graph, residual and constructor checkers.

All 343 historical pure-LP certificates (240 YES and 103 NO) now pass twice
in both checkers. Three synthetic fresh synthesis cases also pass twice per
checker, followed by strict replay using separately distilled, witness-free
route guidance. This is a focused compatibility and smoke checkpoint, not the
full production release replay. Evidence is retained in
`CeTA-Lean/docs/cpf456-integration/graphs-summary.json`.

## LP nontermination witnesses

These forms require `infiniteTrees` and a NO answer. Program and query remain
in `logicProgramInput`; the witness contains only the following fields:

| Constructor | Ordered witness fields |
| --- | --- |
| `lpTocl09SourceLoopProof` | `clauseIndex`, `seed`, `substitution` |
| `lpTocl09SourceTraceProof` | `seed`, `initial`, `steps`, `substitution` |
| `lpTocl09SourceUnifyProof` | `initial`, `prefix`, `steps`, `substitution` |
| `lpTocl09SourceNeutralProof` | `initial`, `prefix`, `clauseIndex`, `neutral`, `substitution`, `substitution` |

The three additional forms have these ordered fields:

| Constructor | Ordered witness fields |
| --- | --- |
| `lpTocl09RecurrentPairProof` | `atomContext`, `termContext`, `firstHole`, `secondHole`, `seed`, `stride`, `pumpBase`, `resetBase`, `pumpGrowth`, `resetGrowth`, `resetOffset`, `keepFirst`, `steps`, `steps` |
| `lpTocl09AffineLoopProof` | `constructor`, `zero`, `environment`, `atomContext`, `steps`, `prefixes`, `affine`, `affine` |
| `lpTocl09PatternLoopProof` | `atomContext`, `substitution`, `substitution`, `steps`, `prefixes`, optional `acceleration` |

Recurrent traces are ordered as pump then reset; holes are variables and the
seed is a term. `keepFirst` is `true` or `false`. Affine expressions contain
`first`, `second`, `constant` natural coefficients. Affine prefixes contain
`affineSuccess` or `resolvePattern`; pattern prefixes contain `successPattern`,
`successInstance` or `resolvePattern`. Their substitutions and traces retain
the exact order of the verified XML parsers. Pattern acceleration contains an
atom, five substitutions, factor and offset; both numbers must be at most 16,
matching CeTA's existing parser-level limit. This does not replace checking
the acceleration's mathematical obligations.

The corresponding Isabelle criteria and soundness theorems are in
`LP_Recurrent_Pair_Check.thy`, `LP_Affine_Loop.thy`, `LP_Pattern_Trace.thy`
and `LP_Pattern_Acceleration.thy`, with the structured parsers in their XML
theories. LeTA's existing native recurrent, affine and pattern checkers and
soundness proofs independently check these decoded witnesses.

Clause and neutral-argument indices are zero-based. Match steps carry a clause
index and one substitution. Unification steps carry a clause index followed
by source and clause substitutions, in that order. Neutral witnesses end with
entry and recurrence substitutions. Each binding has a variable and a term;
`initial` is an atom. The exact verified criteria remain in
`LP_Source_Loop_XML.thy`, `LP_Source_Trace_XML.thy` and
`LP_Source_Unify_XML.thy`, with independent native LeTA counterparts.

Ferrum's TOCL09 probe and common `prove-lp` export paths apply
`export_migrated` to the implemented constructors. The common command audits
the exported document against its source before invoking the checker. Other outer constructors still retain their old structured
format pending their migration; this staging helper must disappear when all
forms are covered. Internal recursive fragments remain structured and are
not exported as separate file dependencies. The eighteen integrated forms remain self-contained.

## Reproduction

Regenerate the schema with `python3 scripts/generate_cpf6_schema.py`.
Ferrum's `cpf6_lp_codec` example converts supported fragments to CPF 6 and
back, without proving them:

```
cargo run --example cpf6_lp_codec -- encode fragment.xml proof.xml
cargo run --example cpf6_lp_codec -- decode proof.xml fragment.xml
```

The focused integration test is `tests/unified/check_cpf6_lp.py`, taking
`--ceta` and `--codec` paths. It checks schema validity, exact structured
round trips, generated-checker acceptance, and rejection of altered claims,
versions, semantics, queries, duplicated source fields and false child proofs.

## Initial dependency triples

`lpInitialDependencyTriplesProof` uses the source program and query in the
CPF6 input. Its ordered fields are `returns`, `fallback`,
`programContinuations`, `marks`, `argumentFilter`, `ranks`, `components`,
`triples`, and `tripleContinuations`. Each triple contains a head, successful
prefix and call. Codec reconstruction restores the native initial wrapper and
its `lpDependencyTriplesPiDpProof` child exactly.

The independent checker requires the supplied triple list to equal the full
initial triple list of the source, including order and multiplicity, before
transferring the Pi-DP result to source termination. Supporting-program
termination is not assumed. The criteria follow
`LP_Dependency_Triple_Checker.thy` and `LP_Dependency_Triple_Chains.thy`.
The schema-inheritance and six codec tests pass; the focused LeTA gate passes
40 dual-checker checks. Fresh synthesis and strict guided replay also pass
source audits and two checks per checker, with four distilled state-local
actions. Results are retained in
`CeTA-Lean/docs/cpf456-integration/triples-summary.json`. This brings the
focused integration coverage to seventeen forms; full release replay remains
outstanding.

## Symbolic evaluation graphs

`lpSymbolicGraphTerminationProof` requires an infinite-tree YES termination
claim. Source program and query occur only in `logicProgramInput`; ordered
witness fields are `fuel`, `root`, `nodes`, `rules`, `trsTerminationProof`.
Each node contains `goals`, `ground` (variable names), `symbol`, and one
`success`, `resolve`, `instance` or `split` action. Resolve child indices use
zero for no child and positive values for one-based node indices; instance
and split targets are zero-based, matching the native parser.

The root goals must represent precisely the source query and arity, with the
root ground-variable list matching the declared ground argument positions.
Every node is checked, and every source clause must have its corresponding
resolve branch. Interface restrictions and exact extracted-rule membership
justify graph edges. Cycles require full termination of the supplied TRS;
innermost termination alone is insufficient. The child proof is checked by
the ordinary independent TRS checker.

The mathematical correspondence is `LP_SEG_Check.thy`, `LP_SEG_Graph.thy` and
`LP_SEG_Certificate.thy`, with independent LeTA proofs in the `Symbolic*`
modules. Twenty-one executable graph checks and 44 dual-checker CPF6 certificate
checks pass. Fresh synthesis and strict witness-free replay pass source audits
and two checks by each checker. This raises focused integration coverage to
eighteen forms; it does not close the remaining cut/Prolog migration or the
full production replay. Retained evidence is in
`CeTA-Lean/docs/cpf456-integration/symbolic-summary.json`.

## Ordered cut source nontermination

`lpCutSourceNonterminationProof` uses a `logicProgramWithCutInput` containing
`executionSemantics` = `orderedCutMgu`, an ordered `program`, and a `query`
with `predicate` and boolean `modes`. The property is termination and the
answer is NO. This denotes the existing ordered cut MGU source relation;
it does not assert finite-tree occurs-check execution or full Prolog semantics.
The predicate and data symbol strings retain Ferrum's arity-qualified source
encoding. Source equality is independently audited against the input file.

The witness fields, in order, are `fuel`, `arguments`, `core`, `before`,
`after`, `prefix`, and `loop`. Terms use `<var>` or `<funapp>` with a typed
cut symbol followed directly by its argument terms. User symbols and control
symbols remain distinct. Goal and stack constructors retain explicit cut
scopes, clause indices and barriers. Each trace step contains one action
and its complete successor state; resolution actions retain freshness
prefixes, ordered variables, substitution images and any checked output swap.
The schema is `cpf6-cut.xsd`, generated by
`scripts/generate_cpf6_cut_schema.py`.

The independent criterion is LeTA's `Cut.NoProblem.check` and its `sound`
theorem, corresponding to `LP_Cut_NO_Certificate.thy` and `LP_Cut_NO_XML.thy`.
It checks the source program, query modes and witness arguments, the prefix
from that exact query, a nonempty checked MGU loop, and the pumping suffix
conditions. The CeTA adapter reconstructs the same native parser tuple for
the existing generated checker. There is no opaque witness payload and no
new mathematical acceptance rule in either format adapter.

All eight archived source-NO certificates pass schema validation, round-trip
transport, source audits and two checks by each of CeTA and LeTA. Thirteen
negative mutations also fail, giving 84 dual-checker executions. Fresh
synthesis, strict replay and the common CLI gate pass for all eight sources
(96 additional external checks and 16 internal CeTA checks). An empty
production oracle correctly returns Unknown without a certificate. The
343 historical LP certificates and the focused mode, triples and symbolic
regressions also pass. Evidence and hashes are retained in
`CeTA-Lean/docs/cpf456-integration/cut-no-summary.json`. This is the nineteenth
focused CPF6 form; remaining cut YES and Prolog forms are still pending.

## Cut termination graphs

Three additional graph forms use `logicProgramWithCutInput` and a YES
termination claim. `lpCutGraphTerminationProof` and
`lpCutConstructorGraphTerminationProof` declare `orderedCut`, corresponding
to `lp_cut_source` / LeTA `Cut.Source`. The MGU-specific
`lpCutMguConstructorGraphTerminationProof` declares `orderedCutMgu`,
corresponding to `lp_cut_mgu_source` / `Cut.MguSource`. These are distinct
checker conclusions; changing the declared semantics is rejected.

All three carry `fuel`, `root`, `nodes`, `actions`, `residual`,
`predicateEncoding`, `dataEncoding`, and one complete nested
`certificationProblem`, in that order. The MGU form additionally carries
`freeBlocks` between `nodes` and `actions`. The ordinary graph requires a
TOCL09 termination child; both constructor forms require a constructor-QDP
child. Each child has its own CPF6 source, query, modes, semantics and claim.
The parent checker binds the child to the exact encoded residual program,
query predicate, arity and ground positions, then independently checks it.

Nodes retain their complete execution stack, ground/free-variable knowledge,
guards and residual interface. Links retain normalized interfaces, instance
bindings, scope swaps and the exact residual clause. Typed graph actions
cover all branches of `lpc_action_parser`, including both answer-split forms,
plain/control residuals, guarded resolution and equality. A schema-valid
graph cannot omit a node's action or an operational branch and thereby
establish termination: those are mathematical table-checker obligations.

The correspondence is `LP_Cut_Table_XML.thy`,
`LP_Cut_Constructor_XML.thy`, and `LP_Cut_MGU_XML.thy`, with independent
`GraphProblem.check`/`sound` and `MguGraphProblem.check`/`sound` in LeTA.
The direct XML readers are `CPF/CutGraphSyntax.lean` and `CPF/CutGraph.lean`.

The dual-checker compatibility gate passes all 58 archived embedded obligations
and 37 mutations (380 checks). Fifty-one archived source audits pass; seven
fail identically before and after CPF conversion because old certificates
encode user-defined equality heads as built-in symbols. These remain explicit
source-binding mismatches, not current-source certifications.

Fresh synthesis, strict replay and the common `prove-lp-cut` interface pass
for all three forms, with complete witness-free parent/child guidance
(36 external checks and six internal CeTA checks). A separate bounded replay
of all seven source mismatches freshly certifies `minus4.pl`,
`append_linear.pl` and `psk02.pl`; four return Unknown. The latest complete
baseline uses SEG processors for all seven, so their full current-frontier
preservation belongs to the pending SEG migration, not this graph smoke gate.

The 343 historical pure-LP certificates, cut source-NO gate, unified dispatch
and finite-LP preservation tests pass with the same rebuilt checkers. Evidence,
source/binary hashes and every mismatch/replay disposition are retained in
`CeTA-Lean/docs/cpf456-integration/cut-graphs-summary.json`. Twenty-two focused
CPF6 forms are integrated; full cut/Prolog coverage and final production replay
remain outstanding.

## Dependency-triple residual obligations

`infiniteTrees`), `triples`, `program`, and `query`. Each triple has `head`,
`prefix` and `call`; program clauses and query positions use the existing

The matching `lpDependencyTriplesPiDpProof` contains `returns`, `fallback`,
`tripleContinuations`, `programContinuations`, `marks`, `argumentFilter`,
`ranks`, and `components`, in that order. The translation, variable condition,

checked. This is distinct from `lpInitialDependencyTriplesProof`, whose
ordinary LP input additionally requires the complete initial-triple criterion.

`lpCutSEGDependencyTriplesProof` has an ordered-cut MGU source input and a
YES termination claim. Its fields are `fuel`, `chainPredicate`, `triples`,
`successProgram`, `roots`, `components`, `predicateEncoding`, `dataEncoding`,
and one nested `certificationProblem` with `logicProgramTriplesInput`.
The source graph, return receipts, free-variable knowledge, split evidence,
role encodings and exact child triple/support/query correspondence remain
checked. The Isabelle correspondence is `LP_Cut_SEG_Triple_XML` and
`LP_Dependency_Triple_XML`; LeTA uses its independent `TripleProblem` and
`TriplePiDPProblem` checkers. Schema validity alone is not certification.

The focused triple gate passes the archived source proof plus 13 mutations

## Nested return modules

`lpCutReturnNestedConstructorGraphTerminationProof` uses the ordered-cut MGU
input and a YES termination claim. Its ordered proof fields are `fuel`, `root`,
`height`, `moduleRoot`, `modules`, `moduleActions`, `residual`,
`predicateEncoding`, `dataEncoding`, and a nested `certificationProblem`
with an ordinary LP `lpConstructorQDpTerminationProof` child.

Each `returnModule` retains `nodes`, `returnStates`, `returnSymbol`,
`returnArity`, and `actions`. The separate nested `moduleActions` table supplies
local return actions, `nestedReturnSplit`, or `nestedGroundReturnSplit`.
Split records retain return routing, projection, both referenced modules and
links, and any groundness evidence. The checked structural `height` bounds
recursive module checking; it is proof data, not an implicit implementation
cutoff. Every referenced table row and return-frame/source correspondence is
checked. The residual child is bound to the exact encoded residual and query.

The formal correspondence is `LP_Cut_Return_Nested_XML` and
`LP_Cut_Return_Nested_Certificate`. LeTA decodes directly to its independent
`ReturnNestedProblem`. As in the Isabelle nested checker, the explicit nested
action table governs recursive checking. Every visited module must have an
empty primitive-action list. LeTA checks this before projecting module data;
unvisited modules do not impose an additional premise.

The nested-return integration gate checks all three archived embedded proofs
and mutations (72 checks), plus fresh native/strict/common replay of `short1`

## Projected return graphs

`lpCutProjectedGraphTerminationProof` uses the CPF6
`logicProgramWithCutInput` with `orderedCutMgu` semantics and a termination/YES
claim. Its evidence contains `fuel`, `root`, `height`, `moduleRoot`, `modules`,
`moduleActions`, `residual`, `rules`, `encoding`, `fallback`, `argumentFilter`,
and `trsTerminationProof`, in that order. This is distinct from projected SEG
certificates.

Modules preserve nodes, annotated return states, return symbols/arities and
primitive action tables. Every visited module must have an empty primitive
action table. Projected actions are explicit `projectedPlain` or
`projectedRefreshed` records, or recursive `nestedReturnSplit` and
`nestedGroundReturnSplit` records. Refreshed actions contain their local helper
clauses, the ordinary resolution/equality action, refresh variables and the
left/right observations. Grounded splits retain their groundness evidence.

The source query must admit a finite filtered observation for every permitted
input. Progress uses actual rules in the filtered residual TRS. The child
checks the complete filtered rule list after applying the declared symbol
encoding and fallback; an unfiltered or unrelated TRS proof cannot substitute
for it. Duplicate filter keys retain first-lookup semantics. Recursive module
checking uses the declared structural height and preserves saved alternatives,
return values and scope annotations.

Ferrum and the unified CeTA adapter preserve this structured data when wrapping
and unwrapping the CPF envelope. LeTA parses the same records into its independent
`ProjectedProblem` checker, with a kernel-checked source-root and full-TRS child
soundness proof. The relevant Isabelle theories are
`LP_Cut_Projected_Certificate` and `LP_Cut_Projected_XML`, with their projected
local-action, split and nested-module dependencies. The
[focused checkpoint](../../CeTA-Lean/docs/cpf456-integration/projected-return-summary.json)
records 424 positive/mutation checks, 48 fresh replay checks and 364 historical
checks across both checkers. Six common-scheduler runs add 12 internal CeTA
checks. Historical source mismatches remain explicitly flagged. The full
current-frontier release gate remains unfinished; the uniform-recursion
follow-up is documented below.

## Uniform first-clause recursion

`lpCutUniformRecursionProof` is a CPF6 termination/NO claim over
`logicProgramWithCutInput` with `orderedCutMgu` semantics. The proof fields are
`clause`, `variables`, `callArguments`, and `arguments`. The source program,
query predicate and query modes occur only in the envelope's input.

The selected clause must be the first matching source clause, at the query's
predicate and arity. Its head contains distinct variables and its body consists
of a single recursive call of the same arity, using only those head variables.
The supplied initial arguments must all be ground, including arguments for
output-mode positions. This supplies a permitted nonterminating query instance.
The rule permits changing and growing recursive arguments; it does not require
a repeated state or a finite lasso.

LeTA's independent `UniformProblem.check` follows
`LP_Cut_Uniform_Recursion_XML.lpc_uniform_check`. Its soundness proof constructs
a strict source path for every iteration, with fresh scopes and preserved saved
alternatives, then derives nontermination. CeTA's CPF adapter routes the same
structured evidence to its existing generated checker. The
[focused checkpoint](../../CeTA-Lean/docs/cpf456-integration/uniform-summary.json)
records 252 positive/mutation checks, 40 fresh common-scheduler replay checks
and 364 historical checks across both checkers. Ten common-scheduler runs add
20 internal CeTA checks. Historical source mismatches remain flagged. All 18
inventoried cut constructors now have CPF6 transport, but full current-frontier
release parity and Prolog migration remain unfinished.

## Static Prolog source bridges

The three static bridges use `prologInput` in the CPF6 envelope. It contains
`executionProfile`, the complete typed `program`, and `query` with its
predicate and modes. The supported profile is `iso-rational-libraries-v1`.
These fields describe the lowered Prolog source obligation; Ferrum separately
audits its correspondence to the original Prolog source file.

The proof contains `predicates` (name/arity signatures) and a complete child
`certificationProblem`. The permitted pairs are:

| Prolog proof | Answer | Child proof |
| --- | --- | --- |
| `prologStaticSEGProof` | YES | `lpCutSEGDependencyTriplesProof` |
| `prologStaticNonterminationProof` | NO | `lpCutSourceNonterminationProof` |
| `prologStaticUniformRecursionProof` | NO | `lpCutUniformRecursionProof` |

Outer and child programs, query predicates and modes must match. A child proof
of another source obligation cannot establish the enclosing Prolog claim.
The fixed builtin signature comes from `LP_Prolog_Builtin_Signature`; it is
not certificate data. The declared predicate set must contain the query,
cover every static body call, and exclude builtins. For NO, every declared
predicate must also be defined in the source program. Undefined calls abort
the computation and therefore cannot justify an ordinary-LP loop in Prolog.

LeTA independently implements the three corresponding Isabelle criteria from
`LP_Prolog_Static_XML`, `LP_Prolog_Static_NO_XML`, and
`LP_Prolog_Uniform_NO_XML`. Its soundness proofs distinguish termination's
error overapproximation from nontermination's suppression of ordinary
dispatch at undefined and builtin calls. This section specifies the static
forms; it does not claim migration of the remaining Prolog constructors or
completion of the all-category release gate.

The [static Prolog checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-static-summary.json)
records 176 positive/negative checks across both checkers, eight fresh native
and strict outputs with source audits, 16 internal CeTA checks, and preservation
of all 91 historical cut obligations (364 checks). The 11 previously recorded
historical source mismatches remain flagged.

## Undefined Prolog entry

`prologUndefinedQueryProof` uses a termination/YES CPF6 claim over
`prologInput`. The input includes the complete lowered program, including the
profile's library clauses, and the query/modes. The proof's `definitions`
list must equal the user-symbol definition signatures extracted from that
program's ordered clause heads. Signatures retain multiplicity and arity.

The entry signature must be absent from that complete list and from the fixed
builtin signature. No clause body is reached: an undefined entry raises an
uncaught existence error and clears the whole computation. Consequently,
unreachable bodies are retained without imposing static-body restrictions.
They still must parse as valid typed source goals. The independent Lean
criterion checks undefinedness directly against the parsed program.

The former signature-only native certificate cannot supply the program for a
CPF6 conversion. Fresh Ferrum reconstruction supplies it from the original
source; the original-source audit also compares unreachable bodies. Changing
both the program and its signatures creates a different embedded obligation,
which must not be counted as a proof of the original source file.

The [undefined-entry checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-undefined-summary.json)
records 224 dual-checker checks, eight fresh native/strict outputs, 24 explicit
source audits and preservation of the preceding 176-check static Prolog gate.
The full CPF4/5/6 release gate remains unfinished.


## Primitive Prolog return tables

`prologVarReturnDependencyTriplesProof` is a termination/YES claim over the
complete `prologInput` program, profile and query. Its proof fields are `fuel`,
`root`, `nodes`, `returnStates`, `returnSymbol`, `returnArity`, `actions`,
`residual`, `predicateEncoding`, `dataEncoding`, and a child
`certificationProblem`. The child must use `lpInitialDependencyTriplesProof`;
a dependency-triple chain claim by itself does not prove the required initial
residual query terminates.

Actions are ordinary `cut` return actions, `variableTest` or `identityTest`.
Variable tests cover `var`, `nonvar`, `compound` and `atomic`; identity tests
cover `==` and `\==`. Each test retains the argument terms, continuation goals,
active terms, saved return state and both outcome links. The checker determines
which outcomes are possible and verifies all required links. An identity
observation adds an equality only to the branch that establishes equality.
Ordinary cut dispatch is forbidden at builtin calls. Unsupported source builtin
signatures and unsupported action constructors are rejected.

Ferrum reconstructs this envelope before source auditing and export. Unified
CeTA decodes it into its existing formalized criterion; LeTA independently
checks the source, table, returned environments and complete residual child.
The [primitive-return checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-return-summary.json)
records 420 dual-checker checks, fourteen fresh native/strict proofs, source
binding audits and preservation of the earlier Prolog gates. Further Prolog
forms and the full CPF4/5/6 release gate remain unfinished.


## Modular Prolog return tables

`prologModularReturnDependencyTriplesProof` has the same CPF6 source, query,
residual and initial-LP child fields as the primitive return form. Its `actions`
add `trimBarriers`, `parallelAlternatives` and `refutedGuard` to the primitive
Prolog return actions. Primitive actions retain their existing XML shape.

`trimBarriers` contains two `returnState` fields and a `link`. The current state
must equal the successor followed by the supplied barrier suffix; every entry
in that suffix must be a barrier. `parallelAlternatives` contains `links`, one
for each current frame. Every alternative is checked with its own saved answer
environment. `refutedGuard` contains `index`, `prefix` and `bindings`; it closes
a node only when the indexed path guard is proved impossible. An out-of-range
index or an unjustified refutation is rejected.

The modular soundness argument preserves every surviving suffix after a cut
or builtin error and preserves the saved environments under successful builtin
substitution. All return links still require residual progress, and the nested
CPF child must prove the complete initial residual query terminates.


The [modular-return checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-modular-summary.json)
records 224 positive/negative checks in unified CeTA and independent LeTA,
six fresh native/strict proofs, fifteen source audits and the frozen binary
identities. It is a focused integration gate, not the full CPF4/5/6 release.


## Prolog nontermination after builtin tests

`prologTestSourceNonterminationProof` is a termination/NO claim over the complete
`prologInput` program, execution profile and query. Its proof fields are
`predicates`, `fuel`, `arguments`, `core`, `before`, `after`, `prefix` and `loop`.
The query arguments must have the declared arity and satisfy its ground modes.

Each prefix `step` contains either `ordinary` with one cut nontermination action,
or the empty `test` element, followed by its resulting `state`. Ordinary dispatch
requires a defined, non-builtin selected predicate. Tests execute exact finite
`var`, `nonvar`, `compound`, `atomic`, identity and inequality observations.
Failed tests resume saved alternatives; undefined ordinary calls cannot be
traversed as backtracking steps.

The nonempty `loop` contains ordinary cut nontermination steps. Its source
component is identified by predicate signatures, including arities. Every
signature must be defined and exclude builtins. Every clause head capable of
resolving a component call must have a static body in that same component.
Unrelated clauses may retain builtin-bearing bodies, but are still part of the
embedded source and original-source audit. The checked prefix must reach the
claimed component state. The loop must pump that state with the required
barrier or suffix-safety conditions; mere syntactic recurrence is insufficient.

Ferrum's NO-query image audit uses complete scalar text, including split XML
text/CDATA fragments, and rejects nested elements in symbol scalars. Schema
validity alone establishes none of the operational or source-binding premises.


The [test-prefix checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-test-no-summary.json)
records 476 dual-checker checks, fourteen fresh native/strict proofs, 35 source
audits and preservation of all 1,044 preceding Prolog checks. Schema validation
covers the semantic mutations separately. This remains a focused gate; full
CPF4/5/6 migration and all-category release validation are unfinished.


`prologRationalSourceNonterminationProof` is a CPF6 NO proof over the complete
`prologInput`. Ordered fields are `predicates`, `fuel`, `arguments`, `graph`,
`anchors`, `variable`, `rhs`, `bindingRoot`, `call`, `callRoot`, `before`, `after`,
`prefix` and `loop`. Nodes contain a cut symbol and child references. Anchors
must derive every graph equation from the source equality; arbitrary closed
solutions for unconstrained variables are invalid. The finite prefix reaches a
checked most-general binding and the loop call, preserving saved alternatives.

Rational actions are `admin`, `case`, `resolve` with environment and body, and
`backtrack` with constructor-clash or repeated-variable observation paths.
Environments use first-binding lookup. Different indices alone never establish
disequality. Reference bounds, exact successors, body-variable coverage, scopes,
whole-program staticness, defined non-builtin predicates, query modes and the
execution profile are checked. A nonempty suffix-safe loop proves source
nontermination. Schema validity alone is not certification.

The fresh rational gate passes 368 checks across four sources and eight
native/receipt-guided strict outputs, each checked twice by CeTA and twice by
independent LeTA. The full migration and all-category gates remain unfinished.

The [rational integration checkpoint](../../CeTA-Lean/docs/cpf456-integration/prolog-rational-summary.json)
also records all 1,520 prior Prolog regression checks passing with the same
binary hashes. The archive preserves source, proofs, guidance, mutations and
checker logs. This completes one form, not the full CPF4/5/6 migration.


`prologIntegerSourceNonterminationProof` carries a CPF6 NO claim over the
complete `prologInput`. Its ordered proof fields are `fuel`, `arguments`,
`core`, `before`, `after`, `prefix` and `loop`. Each trace step carries an
`ordinary` cut action, an empty `test`, or `integerIdentity` containing an
arbitrary-precision signed `integer`, followed by the resulting `state`.
The identity action checks the exact literal operation `N is N`, using the
reserved canonical integer representation. Numeric-looking atoms do not qualify.
The complete source criterion checks the execution profile, source program,
query arity and ground modes, exact trace successors, barrier-only saved
suffixes and a nonempty pumping loop. This NO criterion remains sound for
builtin relations containing the checked operations; it does not implement
general arithmetic evaluation or establish termination.

Integer transport is implemented in Ferrum, unified CeTA and independent LeTA.
The fresh integer gate passes 208 dual-checker checks over four sources and
eight native/receipt-guided strict certificates. Prior-form regressions are
running; the archived integration checkpoint remains pending. Full migration
and all-category release validation remain unfinished.


`prologGroundIntegerSourceNonterminationProof` uses the same source envelope
and ordered fields as the integer-identity NO form. Its trace actions also
include `integerComparison`, with ordered `left`, `right` and `holds` children.
Each side contains an expression receipt: `integer`, `var`, `positive`,
`negate`, `add`, `subtract`, `multiply`, `divide` or `modulo`. Unary operations
have one expression; binary arithmetic has two; division and modulo have an
expression followed by a signed integer `divisor`. Ground-comparison receipts
must pass the semantic expression check with an empty variable domain and
nonzero divisors. The complete source term must equal the receipt term.

Comparison names and operand order come from the source call. The checked
Boolean result either retains the remaining current goals or resumes saved
alternatives. Both outcomes require complete integer evaluation evidence.
Ferrum conversion, unified CeTA transport, the typed LeTA reader and the
structured schema are implemented. Twenty codec tests, twenty-one parser
checks and three schema inheritance tests pass. Fresh certification and replay
are pending; this is not yet a completed migration checkpoint.
